How upload, Mistral OCR, the LLM, and LangGraph work together

This page explains the current implementation and the change needed if extracted questions should only enter the real Question Bank after a teacher clicks Approve.

1. Big picture

Upload is intentionally asynchronous. The frontend uploads a PDF and gets an IngestionJob. A background management command later runs the extraction graph. The graph either uses Gemini native-PDF extraction or the experimental Mistral OCR batch pipeline. 

flowchart TD
  A[Teacher uploads PDF] --> B[bank.views.ingest]
  B --> C[Create IngestionJob: pending]
  C --> D[drain_ingestion_jobs command]
  D --> E{EXTRACTION_PIPELINE}
  E -->|gemini-native-pdf| F[build_extraction_graph]
  E -->|mistral-ocr-batch| G[build_ocr_batch_extraction_graph]
  F --> H[LLM extracts structured JSON]
  G --> I[Mistral OCR gives markdown]
  I --> J[LLM structures markdown into JSON]
  H --> K[Ingestor.ingest_extracted]
  J --> K
  K --> L[Question.objects.bulk_create]
  L --> M[Scrollable extracted question review]
Current behavior: by the time the scrollable review list appears, the rows are already persisted as Question records.

2. Current frontend/backend flow

Frontend upload

useIngestionUpload.upload() calls uploadIngestionPdf().

Backend queue

bank.views.ingest() creates an IngestionJob. No OCR or LLM call happens in the HTTP request.

Background drain

drain_ingestion_jobs.Command._process() runs or resumes the LangGraph thread.

Review list

fetchIngestionJobQuestions() calls bank.views.ingest_questions() and renders ExtractedQuestionsPanel.

3. How Mistral OCR and the LLM work together

Mistral OCR does not decide what a valid bank question is. Its job is to turn PDF pages into markdown. The configured extraction LLM then reads that markdown and emits structured JSON matching the question schema. 

sequenceDiagram
  participant PDF as Uploaded PDF bytes
  participant OCR as MistralOcrClient.process_pdf
  participant Filter as pages_from_ocr_response + is_english_question_page
  participant Batch as batch_ocr_markdown
  participant LLM as MistralOcrMarkdownExtractor.structure_markdown
  participant Parse as _parse_json_response
  participant Tail as Ingestor.ingest_extracted

  PDF->>OCR: base64 PDF to /v1/ocr
  OCR-->>Filter: pages with markdown/text
  Filter-->>Batch: English question pages only
  Batch-->>LLM: combined OCR markdown
  LLM->>LLM: _markdown_extraction_prompt(markdown, schema)
  LLM->>LLM: chat_model.invoke([HumanMessage])
  LLM-->>Parse: JSON text
  Parse-->>Tail: { questions: [...] }
backend/bank/ocr_extractor.py
  MistralOcrClient.process_pdf(pdf_bytes)
  pages_from_ocr_response(ocr)
  is_english_question_page(markdown)
  batch_ocr_markdown(pages)
  MistralOcrMarkdownExtractor.structure_markdown(markdown)
  _markdown_extraction_prompt(markdown, schema)
  _parse_json_response(response.content)

4. How LangGraph is used

LangGraph is the resumable orchestration layer. It stores progress under a stable thread_id, so a killed process can resume without repeating already-checkpointed work.

OCR batch graph shape

flowchart TD
  A[StateGraph OcrBatchExtractionState] --> B[Node: plan]
  B --> C{_next_ocr_batch_step}
  C -->|more batches| D[Node: structure_batch]
  D --> E{_next_ocr_batch_step}
  E -->|more batches| D
  C -->|all done| F[Node: persist]
  E -->|all done| F
  F --> G[END]

Exact LangGraph code concepts

ConceptExact codeMeaning
State OcrBatchExtractionState The typed dictionary carried between graph nodes.
Reducer annotation payloads: Annotated[list[dict], operator.add] When a node returns a new payload list, LangGraph appends it to existing payloads instead of replacing it.
Nodes plan, structure_batch, persist Python functions registered with graph.add_node(...).
Conditional edge graph.add_conditional_edges(..., _next_ocr_batch_step) Chooses whether to loop into another batch or move to persist.
Checkpoint thread {"configurable": {"thread_id": job.thread_id}} Identifies the resumable graph run for this upload.
Synchronous checkpointing graph.invoke(state, config, durability="sync") Writes checkpoints durably after steps so paid work is not lost. 
class OcrBatchExtractionState(TypedDict, total=False):
    job_id: int
    total_pages: int
    batch_pages: int
    next_batch: int
    ocr_pages: list[dict]
    payloads: Annotated[list[dict], operator.add]
    created: int
    skipped: int
graph = StateGraph(OcrBatchExtractionState)
graph.add_node("plan", plan)
graph.add_node("structure_batch", structure_batch)
graph.add_node("persist", persist)
graph.set_entry_point("plan")
graph.add_conditional_edges("plan", _next_ocr_batch_step)
graph.add_conditional_edges("structure_batch", _next_ocr_batch_step)
graph.add_edge("persist", END)
return graph.compile(checkpointer=checkpointer)

5. Where the Approve button should fit

If approval should be the moment a question enters the database as a usable bank question, do not call Ingestor.ingest_extracted() from the graph's persist node. Instead, save extracted items into a candidate/review table, render those candidates, and only create Question rows after approval. 

flowchart TD
  A[PDF upload] --> B[LangGraph: OCR + LLM]
  B --> C[Save ExtractedQuestionCandidate rows]
  C --> D[Scrollable review list]
  D --> E{Teacher action}
  E -->|Approve| F[approve_ingestion_questions endpoint]
  F --> G[Ingestor.ingest_questions]
  G --> H[Question.objects.bulk_create]
  H --> I[Question appears in bank]
  E -->|Reject| J[Candidate status = rejected]

  C:::review
  D:::review
  H:::persisted
  I:::persisted

  classDef review fill:#fef3c7,stroke:#f59e0b,color:#78350f;
  classDef persisted fill:#dcfce7,stroke:#16a34a,color:#14532d;
CurrentApproval-based
persisted before review candidate before review
persist() calls Ingestor.ingest_extracted(). persist() creates candidate rows only.
ingest_questions() returns real Question rows. ingest_questions() should run inside the approve endpoint.
Review list displays BankQuestion[]. Review list should display ExtractedQuestionCandidate[]. 
Suggested backend additions:

class ExtractedQuestionCandidate(models.Model):
    ingestion_job = ForeignKey(IngestionJob, related_name="candidates")
    raw_payload = JSONField()
    status = pending / approved / rejected
    question = nullable ForeignKey(Question)

POST /api/bank/ingest/{job_id}/approve/
  -> approve_ingestion_questions(request, job_id)
  -> Ingestor.ingest_questions(selected_raw_payloads, ...)
  -> Question rows created
